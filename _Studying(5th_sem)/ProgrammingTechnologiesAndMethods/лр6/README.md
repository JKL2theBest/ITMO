# Система Аутентификации и Авторизации (Лабораторная работа №6)

## Описание

Данный проект представляет собой полнофункциональный прототип системы аутентификации и авторизации, реализованный в соответствии с ТЗ лабораторной работы №6 по курсу "Технологии и методы программирования".

Система демонстрирует применение многоуровневой архитектуры, современных практик безопасности (включая **многофакторную аутентификацию**) и принципов чистого кода. Проект включает в себя как **консольный интерфейс** для прямого взаимодействия с ядром системы, так и **веб-интерфейс** на базе FastAPI.

## Технологический стек

-   **Язык:** Python 3.11+
-   **Веб-фреймворк:** FastAPI, Uvicorn
-   **База данных:** SQLite (через `aiosqlite`)
-   **ORM:** SQLAlchemy 2.0 (асинхронный режим)
-   **Хеширование паролей:** Argon2id (через `passlib`)
-   **Многофакторная аутентификация (MFA):** TOTP (Time-Based One-Time Password) через `pyotp`.
-   **Валидация данных:** Pydantic
-   **Тестирование:** Pytest, Pytest-asyncio

## Архитектура

Проект построен на основе многоуровневой архитектуры для четкого разделения ответственности:

-   `web_main.py` / `main.py`: Слой представления (Web API / Консольный интерфейс).
-   `services/`: Слой бизнес-логики (регистрация, вход, авторизация, MFA, управление ролями и сессиями).
-   `db/repository.py`: Слой доступа к данным (инкапсуляция SQL-запросов).
-   `db/models.py`: Слой моделей данных (описание таблиц БД через SQLAlchemy).
-   `core/`: Вспомогательные модули (безопасность, конфигурация).
-   `schemas/`: Схемы Pydantic для валидации данных.
-   `frontend/`: Простой одностраничный HTML-клиент для взаимодействия с Web API.

## Функциональность

### Основные функции
-   **Регистрация** новых пользователей с ролями `user` или `admin`.
-   **Безопасное хранение паролей** с использованием Argon2id и уникальной соли для каждого пароля.
-   **Аутентификация** пользователей по имени и паролю.
-   **Управление сессиями** на основе токенов, хранящихся в базе данных. Сессии имеют ограниченный срок действия (1 час).
-   **Авторизация** на основе ролей. Реализована простая иерархия: `admin` имеет доступ ко всем ресурсам, `user` — только к общим.
-   Корректный **выход из системы** с удалением сессии из БД.

### Дополнительные функции (расширенное ТЗ)
-   **Смена пароля:** Аутентифицированный пользователь может сменить свой пароль, предоставив старый.
-   **Многофакторная аутентификация (MFA/2FA):** Администратор может включить для любого пользователя второй фактор аутентификации (TOTP), совместимый с Google Authenticator, Authy и др.
-   **Управление ролями (только для администраторов):**
    -   Просмотр списка всех ролей в системе.
    -   Создание новых ролей.
    -   Назначение ролей существующим пользователям.

## Запуск и использование

### 1. Требования

-   Python 3.11+
-   `venv` для создания виртуального окружения

### 2. Установка

```bash
# 1. Перейдите в папку проекта (лр6)

# 2. Создайте и активируйте виртуальное окружение
python -m venv venv
# Windows: venv\Scripts\activate
# macOS/Linux: source venv/bin/activate

# 3. Установите все зависимости
pip install -r requirements.txt
```

### 3. Запуск тестов

Для проверки корректности работы модулей ядра (хеширование, бизнес-логика) можно запустить автоматические тесты:

```bash
# Находясь в корневой папке проекта (лр6)
pytest
```
Ожидаемый результат: `9 passed`.

### 4. Запуск приложения

Проект можно запустить в двух режимах:

#### Режим 1: Консольный интерфейс

Этот режим идеален для быстрой проверки и демонстрации логики ядра.

```bash
# Находясь в корневой папке проекта (лр6)
python main.py
```
После запуска приложение выведет список доступных команд: `register`, `login`, `logout`, `chpasswd`, `access`, `list_roles`, `create_role`, `assign_role`, `enable_mfa`, `exit`.

#### Режим 2: Веб-интерфейс + API

Этот режим запускает веб-сервер FastAPI, который предоставляет как API-эндпоинты, так и простой HTML-интерфейс для взаимодействия с ними.

```bash
# Находясь в корневой папке проекта (лр6)
uvicorn web_main:app --reload
```

После запуска будут доступны следующие адреса:

-   **Веб-интерфейс:** `http://127.0.0.1:8000/`
-   **API-документация (Swagger UI):** `http://127.0.0.1:8000/docs`

Через веб-интерфейс можно протестировать весь реализованный функционал, включая админ-панель.
