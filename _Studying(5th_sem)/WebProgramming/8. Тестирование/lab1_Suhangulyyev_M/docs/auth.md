# Ролевая модель и права доступа

Данный документ описывает роли пользователей, способы аутентификации и связанные с ними права доступа.

## Способы аутентификации

Система поддерживает два способа получения токенов доступа (JWT):

1.  **Классическая регистрация/логин:** Через эндпоинты `/auth/register` и `/auth/login` с использованием пары email/пароль.
2.  **GitHub OAuth:** Через эндпоинты `/auth/github/login` и `/auth/github/callback`. При первом входе через GitHub для пользователя автоматически создается аккаунт.

Все защищенные эндпоинты ожидают `access_token` в заголовке `Authorization: Bearer <token>`.

## Роли пользователей

В системе предусмотрено три иерархические роли:

1.  **`USER` (Пользователь)**
2.  **`VERIFIED_AUTHOR` (Верифицированный автор)**
3.  **`ADMIN` (Администратор)**

Каждая последующая роль в иерархии наследует все права предыдущей.

---

### 1. `USER`

Это базовая роль, которая присваивается всем пользователям по умолчанию при регистрации (как через email/пароль, так и через GitHub OAuth).

**Права:**
*   Просматривать любые сущности (новости, комментарии, пользователей).
*   Создавать комментарии к новостям.
*   Редактировать и удалять **только свои** комментарии.
*   Редактировать **только свой** профиль (имя, аватар).
*   Просматривать свои активные сессии и выходить из них (`logout`).
*   Обновлять свой `access_token` с помощью `refresh_token`.

---

### 2. `VERIFIED_AUTHOR`

Эта роль предназначена для пользователей, которым доверено создание контента. Роль назначается администратором (на данный момент - только через прямое изменение в БД).

**Права:**
*   Все права роли `USER`.
*   Создавать новые новости.
*   Редактировать и удалять **только свои** новости.

---

### 3. `ADMIN`

Эта роль обладает полными правами в системе и предназначена для управления контентом и пользователями.

**Права:**
*   Все права ролей `USER` и `VERIFIED_AUTHOR`.
*   Редактировать и удалять **любые** сущности (новости, комментарии) независимо от их авторства.
*   Редактировать профили **любых** пользователей.
*   Удалять **любых** пользователей.

---
## Сводная таблица прав доступа

| Действие | Эндпоинт | `USER` | `VERIFIED_AUTHOR` | `ADMIN` |
| :--- | :--- | :---: | :---: | :---: |
| **Новости** |
| Чтение списка/одной | `GET /news` | ✅ | ✅ | ✅ |
| Создание | `POST /news` | ❌ | ✅ | ✅ |
| Изменение/Удаление | `PATCH/DELETE /news/{id}` | ❌ | 🔒 (только свои) | ✅ |
| **Комментарии** |
| Чтение | `GET /comments` | ✅ | ✅ | ✅ |
| Создание | `POST /comments` | ✅ | ✅ | ✅ |
| Изменение/Удаление | `PATCH/DELETE /comments/{id}`| 🔒 (только свои) | 🔒 (только свои) | ✅ |
| **Пользователи** |
| Чтение списка/одного | `GET /users` | ✅ | ✅ | ✅ |
| Изменение | `PATCH /users/{id}` | 🔒 (только свой) | 🔒 (только свой) | ✅ |
| Удаление | `DELETE /users/{id}` | ❌ | ❌ | ✅ |

**Обозначения:**
*   ✅ - Разрешено
*   ❌ - Запрещено
*   🔒 - Разрешено только для своей сущности
